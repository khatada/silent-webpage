# ピクセルアートの制作・補正・採用

ユーザー指定により、ピクセルアートの原画は `$imagegen` スキルによる画像生成で制作する。プログラムでの原画生成は禁止する。生成済み画像の一部を変更するための一時的なプログラム使用と、ドットずれの補正は許可される。いずれも原画をコードで生成するための例外ではない。

補正後にLLMが画像を実際に確認し、採否を記録してから採用する。自動変換の成功だけでは採用しない。背景、透過素材、アニメーション用の画像にもこの工程を適用する。

## 原画の制作と保存

1. 利用可能なimagegenスキル・画像生成ツールを確認し、画像生成で原画を制作する。コード描画を代替手段にしない。
2. 生成原本を公開ディレクトリ外に保持し、使用ツール・プロンプト・原本への参照を記録する。
3. 必要な部分編集・切り出し・ドット補正を行い、原本との関係と処理設定を追跡できるようにする。
4. 補正後画像をLLMが閲覧して採用を判断する。公開素材にするのは採用後とする。

PixiJSでは採用済み画像の読み込み・配置・移動・透明度変更・画像フレーム切替を行う。Graphicsなどで背景やキャラクターの原画を生成しない。既存の手続き描画は生成素材への移行対象であり、新規追加に使用しない。

## 補正プログラム

```sh
npm run art:correct -- --input original.png --output corrected.png --cell-size 2.25 --offset-x 0 --offset-y 0 --scale 2
```

- `cell-size`: 元画像の1ドットの幅・高さ。小数も指定できる。
- `offset-x/y`: 元の格子原点。0以上、cell-size未満。
- `scale`: 補正後1ドットの整数倍率。1はネイティブ画像。
- 元画像は保持し、出力先の上書きは禁止する。
- 各セルの最多RGBA色を採用。同数の場合はセル中心に近い色を使う。透明度は保持する。端の不完全なセルは切り落とす。
- 出力PNGと `.png.json` の設定・入出力SHA256をセットで保存する。

格子幅は目視と作成時の設定から決める。自動推定や局所的な歪みの自動修復は行わない。ずれた部位が残る、細部が失われる場合は採用せず、格子設定または原画を修正して再実行する。元画像が既に1px格子ならcell-size 1で補正し、変化がないことも確認する。

## LLMによる採否

1. 元画像と補正画像を出力する。アニメーションは代表姿勢とPC・縦長画面を含める。
2. 補正画像をLLMの画像閲覧機能で実際に開く。
3. ドットの整列、輪郭、窓・猫などの細部、配色、構図の破損を確認する。
4. 対象画像・ハッシュ・補正設定・採用/不採用・判断理由を記録する。ファイル名や変換ログのみで採用しない。
5. 不採用なら修正と補正を繰り返す。採用記録を作る前に公開用素材へ反映しない。

ユーザーへの承認依頼は不要。これはエージェント自身が行う確認工程である。

## 必須チェック

`npm run art:check` は `npm run verify` とCIに含む。`art-reviews/manifest.json` の採用記録、補正前後PNGとレポートのSHA256、およびscene.tsから到達する描画ソースのハッシュを検証する。public配下のPNGにも採用記録を要求する。LLMの実際の閲覧をプログラムが証明するものではなく、担当エージェントが閲覧した事実と判断を正しく記録する。生成素材自体と、合成後の代表画面を確認する。画像を移動・切り替えるたびに毎フレームのPNG補正を行う必要はない。

画面表示も物理ピクセルの整数倍率へ整列させる。画面の代表PNGには実際の出力格子に対応するcell-sizeを指定し、追加の破損やずれがないことを確認する。生成素材自体の補正設定は、その原画のドット幅と原点に合わせる。補正が冪等な場合も工程を省略しない。

## 代表画像の再出力

本番previewを127.0.0.1:4173で起動し、`npm run art:capture -- --output art-reviews/新しい名前` を実行する。必要なら `ART_BROWSER_PATH=/usr/bin/chromium` でローカルブラウザを指定する。PC・DPR 2のモバイル・狭幅・横向き・横長・小型端末・倍率境界を撮影し、最新ビルドと補正画像を作る。出力先は新規ディレクトリを使う。このコマンドは自動採用しない。画像を閲覧した後、capture.jsonのsourceSha256と画像ごとの採否をmanifest.jsonへ記録する。これは描画の証跡作成であり、コミット前にPlaywrightテスト全体の成功を要求するものではない。

補正レポートとcapture.jsonのPENDING表示は自動採用をしないことを示す生成時の状態として保持する。実際の採否はmanifest.jsonに記録する。

## 生成した猫フレームの表示確認

`npm run art:preview-cat -- --output art-reviews/既存ディレクトリ` は、採用済み生成画像を本番と同じ `createImageCat` と `catPose` で配置する。左右各8枚の歩行、座位・毛づくろい2姿勢・丸まり・左右の伸び、同じ生成済み床画像上で実際の移動を含む16コマ、座位→毛づくろい9区間→丸まりの左右各11コマを1回描画し、最終canvas格子で補正する。原画の制作処理は含まない。Viteの一時ページは127.0.0.1:4174を使い、必要ならART_BROWSER_PATHを指定する。出力画像とメタデータを閲覧してから採否をmanifestへ記録する。全景では画面別倍率も確認する。


## 窓の表示確認

`npm run art:preview-windows -- --output art-reviews/既存ディレクトリ` で、標準・横長・縦長の生成済み背景から各9窓の周囲を切り出し、点灯・遷移中・消灯を並べる。元画像のcropと消灯用の壁cropのSprite合成だけを行い、原画は制作しない。共通runnerが最終格子で補正し、LLMが実閲覧して採否を記録する。各背景の3行は順に点灯・中間・消灯、各列はwindows配列順。初期状態の全景と合わせて窓枠・色・位置を確認する。
